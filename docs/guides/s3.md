# S3 and the workspace

Every path in Alchemist goes through [cloudpathlib](https://cloudpathlib.drivendata.org), and every query goes through
DuckDB, so the same code runs on S3, on a laptop and in tests. Switching to S3 is a matter of settings.

## Use S3 for the workspace

```bash
export ALC_WORKSPACE=s3://alchemist-workspace
```

Each workspace, project, question and run then gets its own S3 prefix, used as its filesystem:

```text
s3://alchemist-workspace/
  workspaces/<workspace>/
    workspace.yaml
    projects/<project>/
      project.yaml
      knowledge/
      questions/<question-id>/
        question.yaml                # text, asker, scope, plan, status
        runs/<run-id>/
          manifest.json  findings.json  notebook.ipynb  SEALED
          inputs/  work/  figures/  report/  logs/
```

Question and run ids are ULIDs, so they sort by time. See [Run folder](../reference/run-folder.md) for what each file
holds.

## Register S3 datasets

Register datasets with `s3://` prefixes ([catalog admin guide](catalog-admin.md)). When a run's views include S3 data,
the kernel's DuckDB connection loads `httpfs` and creates an S3 secret with the `credential_chain` provider, so it uses
whatever AWS credentials the environment provides. No keys are written to code or the notebook.

Globs are expanded with cloudpathlib once per query, and each object's key, ETag, size and last-modified time is
recorded before the query runs on that explicit list.

## Credentials

In the MVP the process uses its own AWS credentials, and access rules are enforced in the tool layer. In the target
design, a credential broker issues each run a short-lived role that can read only the registered prefixes of the run's
plants and write only its own run folder, and the sandbox has no route to the model or the internet. See
[MVP and target design](../design.md); the broker and its grant file are described in
[Deployment contract](../reference/deployment.md#credential-broker).

## Other stores

The catalog database (`ALC_DB`) and the access file (`ALC_ACCESS`) stay local in the MVP. The knowledge root
(`ALC_KNOWLEDGE`) is read through cloudpathlib and may be an `s3://` prefix.
